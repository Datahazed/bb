The Tools hub

One place to find and manage everything that extends bb — Skills, Automations, and Plugins. Today these are three unrelated surfaces. This proposal treats them as one primitive — a Tool — so three data shapes read through a single page grammar and one status vocabulary.

One primitive, three kinds

Skills

Reusable know-how a model can invoke. Authored as SKILL.md on disk; some are read-only (built-in / provider), some you own and edit.

provider · scope · path

Automations

Scheduled or triggered delegated work — an agent prompt or a script that runs on a cron. Active or paused; each keeps a run history.

schedule · next run · last status

Plugins

Installed packages that contribute panels, commands, and settings. Enable, disable, and configure through a declarative settings form.

version · status · settings
Shared page grammar

Every Overview

Header: title + count, search, New…, sort
Card collection, grouped where it means something
Same card anatomy across kinds; only metadata differs
States: loading · empty · error · no-results

Every Detail

Back link to its overview
Header: icon · name · status · primary action · ⋯
Kind-specific body: README / config / permissions / runs
One status system, placed by kind — Skills show scope (read-only / editable); Automations & Plugins toggle Enabled · Paused · Error
Three directions to compare

A · Marketplace Gallery

Top segmented tabs, a rich responsive card grid, full-page detail with a metadata rail. Discovery-forward.

Tradeoff: most browsable; full-page detail risks pogo-sticking when managing many items.

B · Two-Pane Console

A kind-rail plus a compact card list on the left; the selected Tool's detail opens in place on the right. Manage-forward.

Tradeoff: fastest to manage and hop between items; needs horizontal width.

C · Quiet System List

Shallow left sub-nav; wide, calm card rows grouped by status; full-page stacked detail. Settings-native.

Tradeoff: calmest and most consistent with bb; lowest “discover something new” energy.
Recommendation. Ship B’s two-pane shell as the manage surface — no pogo-sticking, and bb users already know the pattern from VS Code — rendering list items in C’s calm card style. A’s gallery grid also powers Browse — the skills.sh registry — where one-click install lands a skill across every provider. One card, one status system, three kinds, plus a registry.
Competitive landscape
How ~19 agent tools handle extensibility

Conductor · Emdash · Superset · Tembo · Devin · Factory · Cline · Roo · Kilo · Cursor (+ Terragon / Amp / Charlie / Async / Vibe Kanban / Crystal / Claude Squad / Uzi / Cmux). The finding: unified hubs are emerging, but none are card-based and none fold in scheduled automations with run history — the combination bb’s Tools hub would own.
Grounded in real components

Every color is a real bb token (the --canvas/--ink mix system from theme.css), rendered in light and dark. Components — Card, Pill, Switch, StatusDot, EmptyStatePanel, Skeleton — and the data fields (SkillSummary, AutomationResponse, PluginListItem) mirror PR #407. Anything net-new is labelled proposed.

These are static wireframes, not the built UI. Per-kind accent color is deliberate: the Tools hub is the one surface where color earns its place — telling Skills, Automations, and Plugins apart at a glance — while the rest of bb stays monochrome. The Skills area indexes the skills.sh registry — a Browse mode with one-click install (npx skills add owner/repo) across your configured providers.
